# Что интересного? — первая версия

Цель: Telegram Menu Button → React/Vite на GitHub Pages → HTTPS Supabase Edge Function → PostgreSQL → ответ внутри Mini App. Локальный бот и старое меню остаются отдельными работающими версиями. Новостей из памяти модели, платных API и локального ИИ в этой версии нет.

Интерфейс: четыре знакомые цветные карточки с уже созданными значками Flow. Синий #1d4ed8 — погода, янтарный #b45309 — политика, фиолетовый #7e22ce — нейросети, бирюзовый #0f766e — интересное. Основной фон #f3f5fa, текст #142139, тёмная тема берёт цвета Telegram. Системный шрифт Segoe UI/system-ui обеспечивает быстрый запуск без внешних шрифтов. Вверху название и подзаголовок, ниже карточки, поле запроса; отдельный экран результата с обновлением и раскрываемыми подробностями, вкладка истории. Всё выровнено влево. Изображения — единственный декоративный акцент; анимации интерфейса отвечают действиям пользователя и учитывают reduced motion.

Авторизация: только исходная initData, HMAC SHA-256 по документации Telegram, срок 1 час, допуск будущего времени 30 с, точное сравнение ID с разрешённым серверным ID. initDataUnsafe не используется. Все четыре действия auth/create/status/history защищены. Origin разрешён только https://maxhandhunt-hub.github.io; отсутствие Origin допустимо для серверного теста с той же подписью. Публичного обхода авторизации нет.

Одна Edge Function telegram-app обрабатывает четыре именованных действия. Таблицы jobs/results недоступны anon/authenticated, RLS включён без публичных политик. Только серверный ключ обращается к БД; каждый запрос фильтруется по проверенному владельцу. SQL RPC атомарно ограничивает частоту и создаёт задания с UUID идемпотентности. Ответы сохраняются транзакционно. Новостные ответы явно демонстрационные; погодный ответ получает реальные показатели Open-Meteo. Браузер вне Telegram показывает только локальные демонстрационные примеры без запросов к защищённой истории.

Ограничения: 1000 символов в запросе, 16 КиБ в теле HTTPS, 6 новых заданий/мин и 100/сутки, 120 защищённых обращений/мин, до 50 записей истории за раз. Текущая версия исполняет задания сразу в Edge Function; queued зарезервирован для будущего исходящего Windows-воркера. Клиент ограничивает ожидание и сохраняет UUID при повторе после сетевого сбоя.

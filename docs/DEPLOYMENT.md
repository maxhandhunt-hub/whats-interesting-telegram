## Проверки

1. 20 автоматических тестов Vitest: подпись Telegram, другой ID, истечение срока и будущее auth_date, изменение данных, повторные параметры, отсутствие конфигурации; границы запроса и категории; демонстрационная маркировка; реальные поля погоды/пропуски; ограниченные повторы при сбое; возврат результата из one-to-one join; клиентский POST/initData, ошибка сети/авторизации и неполный ответ. Сборка TypeScript + Vite проходит. npm audit при установке: 0 vulnerabilities.
2. На реальном HTTPS backend: четыре категории completed; погода mode=live, новости mode=demo. История и status возвращают сохранённые результаты. Повторный requestId возвращает тот же job, другое содержимое с тем же UUID получает 409. Нет подписи/изменённая подпись/старый вход получают 401, посторонний подписанный ID и чужой Origin — 403. Некорректная категория — 400. Эти серверные тесты подписывались локально существующим токеном и не выдаются за запуск Telegram-клиента.
3. Отдельно пользователь подтвердил реальное открытие новой inline web_app кнопки в @Lmynewsbot и получение погоды внутри Mini App без отдельного основного ответа в чате. Таким образом, основной end-to-end сценарий Telegram → Pages → Supabase → Mini App подтверждён пользователем.
4. PostgreSQL: лимит шести новых заданий в минуту проверен семью вызовами в транзакции с rollback; тестовые записи этого теста не сохранены. Privileges/RLS проверены запросом каталога. Публичный publishable key получил HTTP 401 при попытке читать каждую из трёх таблиц и вызвать begin_job. Один промежуточный HTTP-тест RPC был прерван транспортной TLS-ошибкой; повтор завершился ожидаемым 401, проверка TLS не отключалась.
5. Chrome: четыре категории, открытие ответа, раскрытие подробностей, обновление, возврат, свободный запрос, запрет защищённой истории вне Telegram. Мобильные ширины 390 и 320 px без горизонтального переполнения. Картинки загружаются. После исправления BackButton обычному браузеру не вызывается неподдерживаемый Telegram API. Скриншоты сохранены локально в docs/evidence, не опубликованы.
6. Проверка исходников/сборки на точные значения реального токена и ID прошла. Тело запроса/initData, секреты и сырые исключения код не журналирует. Клиент не содержит service-role ключ и не использует initDataUnsafe для доступа.

Ранее обнаруженная ошибка нормализации one-to-one results join исправлена и покрыта регрессионными тестами. Неразрешённых падений тестов нет. Светлая/тёмная тема реализована через API темы Telegram и CSS; отдельный визуальный прогон всех тёмных тем и устройств не выполнен. Защищённая история проверена на сервере, но её просмотр в Telegram-клиенте отдельно пользователем не подтверждался. Веб-поиск новостей и локальный ИИ намеренно не проверялись, так как их в этой версии нет. Нагрузочные проверки квот бесплатного тарифа не выполнялись.

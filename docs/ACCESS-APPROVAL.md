# Доступ гостей через одобрение владельца

Существующий бот @LMYHotNewsBot, GitHub Pages и локальный ChatGPT worker сохранены. Отдельный платный API не подключался. Гости расходуют общий локальный лимит запросов и лимит подписки владельца; один запрос выполняется за раз, кэш и ограничения остаются прежними.

## Поведение

/start доступен всем в личном чате: только одна кнопка открытия Mini App. Четыре услуги доступны только внутри Mini App; старые chat-кнопки перенаправляют в Mini App. Дополнительно настроена постоянная Menu Button. Telegram требует нажатия пользователя и не позволяет боту принудительно открыть WebView сразу после /start. При выборе раздела неизвестным пользователем запрос сохраняется, владельцу приходит имя, @никнейм (или «не указан»), Telegram ID, раздел и кнопки «Разрешить»/«Отклонить». Только callback владельца из его личного чата и с точным message_id может принять решение. Сообщение удаляется; при недоступности удаления кнопки отключаются. Одобрение постоянное для этого бота; повторная заявка после отказа ограничена 10 минутами. Заявки действуют 24 часа, одна ожидающая на человека, максимум 100 ожидающих. Повторное одобрение не создаёт задание повторно.

При выборе в чате ответ приходит в чат. При выборе внутри Mini App сайт ожидает решения и автоматически показывает результат того же запроса внутри приложения. Отказ отображается в Mini App и отправляется пользователю в Telegram, если бот имеет право отправлять ему сообщения. Для надёжной доставки уведомлений пользователь и владелец должны нажать /start в новом боте. Закрытие сайта не отменяет заявку: результат будет в личной истории после разрешения. История изолирована по проверенному Telegram ID.

## Сервер и безопасность

Новые закрытые таблицы bot_control, bot_members, access_requests, chat_deliveries с RLS и без разрешений anon/authenticated. Секрет нового бота используется только Edge Function из существующего TELEGRAM_BOT_TOKEN. Webhook на /telegram-app?telegram=1 проверяет X-Telegram-Bot-Api-Secret-Token; секрет вычисляется сервером HMAC от токена и не публикуется. Настройка webhook выполняется авторизованным локальным worker при heartbeat, без извлечения нового Telegram-токена на ноутбук. При замене бота разрешения предыдущего bot_id не переносятся.

Идентичность гостя Mini App сначала подтверждается HMAC Telegram и auth_date; проверка подписи отделена от решения о доступе. Неизвестному ID доступны только создание собственной заявки и чтение её статуса; история и задания закрыты до одобрения. Worker получает задания владельца и явно разрешённых гостей; секрет ChatGPT остаётся локально. Общая очередь ограничена тремя активными новостными заданиями. Отправка длинных ответов в чат разбивается на сообщения, прогресс доставки хранится в БД. Сетевой обрыв в момент успешной отправки Telegram до сохранения прогресса теоретически может продублировать один фрагмент, но не запускает GPT заново.

## Изменения

shared/auth.ts, shared/access.ts; supabase/functions/telegram-app/index.ts, access.ts; src/api.ts, src/main.tsx. Миграции 20261120152249_bot_access_approval и 20261120152421_fix_guest_queue_alias. Windows EXE совместим с новым протоколом, его пересборка не требуется. Тег before-access-approval-20261120 сохраняет версию для отката к доступу только владельца.

## Проверки

34 TypeScript-теста и 17 Python-тестов; сборка Vite и отдельная проверка типов Edge Function. Реальная SQL rollback-проверка: заявка, подавление дубликатов, запрет чужого решения и неверного message_id, одобрение один раз, обработка гостевого задания локальным worker с lease, отказ и cooldown. Первый SQL прогон обнаружил конфликт имени переменной/алиаса; исправлен отдельной миграцией, повторный прогон прошёл. Поддельный webhook реально получает 401 WEBHOOK_AUTH. Security advisors без WARN/ERROR; INFO о RLS без политик — намеренный запрет публичного доступа.

Финальное получение уведомлений и результата другим реальным Telegram-аккаунтом требует пользовательской проверки; автоматические тестовые подписи и callback-fixtures не выдаются за тест на чужом аккаунте.

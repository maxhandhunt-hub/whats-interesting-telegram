# Этап 2 — реальные новости через локальный ChatGPT

## Что изменено

Сохранены существующие GitHub-репозиторий, URL, Supabase-проект, Telegram-подпись, ID владельца, дизайн, значки и погодный модуль. В рабочем режиме три новостные категории больше не вызывают демонстрационный обработчик. Новости идут по маршруту Mini App → Supabase queued → Windows → GPT через OAuth подписки → проверка → Supabase completed → Mini App. Ошибки не заменяются тестовым ответом. Старые демонстрационные записи остаются в базе для сохранности, но скрыты из новой рабочей истории. Внешний браузер по-прежнему показывает только ограниченный просмотр без авторизации.

Исходники локального приложения опубликованы в этом же репозитории под MIT. `worker/oauth.py` — публичный OAuth/PKCE-клиент; `secure_store.py` — DPAPI; `inference.py` — Responses/SSE; `sources.py` — RSS, официальные релизы и проверка публикаций; `news.py` — обзоры и кэш; `runtime.py` — исходящий worker с арендой; `gui.py` и `run_worker.py` — окно и трей. Зависимости: worker/requirements.txt, сборка: WhatsInterestingWorker.spec. Frontend изменён в src/main.tsx, src/style.css и shared/contracts.ts. Имеющиеся изображения не менялись.

## Официальное подключение ChatGPT

Проверены действующие инструкции OpenAI:

- https://developers.openai.com/siwc/quickstart
- https://developers.openai.com/siwc/token-sharing-open-source
- https://developers.openai.com/siwc/token-sharing-open-source/sign-in
- https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference
- https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations
- https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery
- https://developers.openai.com/cookbook/articles/sign-in-with-chatgpt

Приложение работает локально, не продаёт удалённый inference и не помещает авторизацию ChatGPT на Supabase. Использована ранее выданная этому же локальному приложению OAuth-регистрация с отдельным scope `chatgpt.tokens.use.direct`. Разрешение подтверждено фактическим запросом; токены не извлекались из Chrome, ChatGPT Desktop или Codex. При новом входе используются dynamic_agent_client, стабильный UUID host ID, state, nonce, PKCE S256, loopback 127.0.0.1/auth/callback, проверка ID token через JWKS и повторное использование выданного client_id. Кратковременный loopback-listener нужен только для официального входа; постоянных входящих портов, портов роутера и публичного адреса ноутбука нет.

Модельные запросы: только `https://api.openai.com/v1/responses`, Bearer OAuth, `store=false`, `stream=true`; успех только после `response.completed`. Никаких платных API-ключей, промокредитов, backend-api ChatGPT, Codex app-server/CLI, computer use, MCP, shell или файловых инструментов модели. OpenAI API key переменные не читаются. Модель видит запрос пользователя и публичные публикации, а не локальные настройки или секреты.

На аккаунте реально получен каталог моделей. Проверены ответ `CHATGPT_PLAN_OK` и работа web_search. Рабочая экономичная модель — gpt-6-luna; список перед запросом проверяется по каталогу аккаунта, Astra исключена. Принудительный JSON-режим в пробном запросе не прошёл и не используется: рабочий путь получает текстовый JSON и строго разбирает/проверяет его локально. Если OpenAI явно сообщает unsupported capability для web_search, допускается один анализ уже собранных сегодняшних RSS-публикаций без веб-инструмента; иной биллинг не подключается.

Plus и Pro официально поддерживаются этим механизмом. Переход на Plus 1 декабря 2026 ещё не произошёл и сейчас фактически не проверен. Код не зависит от признака Pro, проверяет доступные модели и обрабатывает ограничения подписки. Конкретная будущая доступность моделей, квота и время её сброса задаются OpenAI, а не этим приложением. Лимиты и разрешение приложения доступны в https://chatgpt.com/settings/usage . При ошибке лимита/авторизации worker приостанавливает новые модельные задания; автоматической платной альтернативы нет.

## Очередь Supabase и безопасность

Существующая функция telegram-app расширена защищёнными worker_ping, worker_claim, worker_complete. Telegram initData проверяется на каждом пользовательском запросе как раньше. Worker использует отдельный случайный 256-битный bearer, сохранённый только локально под DPAPI. Supabase хранит лишь SHA-256 digest в закрытой worker_state. В браузер и модель этот ключ не передаётся; service-role ключ по-прежнему только у Edge Function. Методы worker запрещены при наличии browser Origin и требуют отдельный ключ, который даёт работу только с очередью разрешённого владельца.

Миграция 20261120121435_local_news_worker: worker_state с RLS и отзывом public/anon/authenticated, поля lease_token/lease_until/attempts в jobs, RPC begin_news_job/worker_online/worker_ping/worker_claim/worker_finish и обновлённый expire_jobs. Все новые RPC закрыты для public/anon/authenticated. Лимит очереди — три активных задания; одно выполняется одновременно. Lease — 60 секунд с продлением; повторный complete идемпотентен, старый lease отвергается. После обрыва допускается не более двух получений задания, ожидание ограничено 15 минутами. При выключенном ноутбуке новые новости не создаются, сервер возвращает WORKER_OFFLINE; погода остаётся независимой.

Heartbeat каждые 20 секунд, idle polling каждые 12 секунд. Это также расходует бесплатную квоту Edge Functions; при круглосуточной работе получается примерно 346 тысяч фоновых вызовов за 30 дней плюс пользовательские запросы. Квоты Supabase необходимо учитывать, их превышение может остановить бесплатный сервис; платный тариф и автоматическая оплата не включены. Авторизованные обращения ограничены общим серверным счётчиком, новые задания — 6/мин и 100/сутки.

## Сбор и качество новостей

RSS: BBC, Guardian, ТАСС, ООН, OpenAI, Google AI, Microsoft Research, Hugging Face, NASA, ScienceDaily. Для ИИ дополнительно официальные GitHub Releases OpenAI/Codex, Anthropic/Claude Code, Google/Gemini CLI, Qwen-Agent и Transformers. Каждый URL ленты проверен; несуществующие RSS Anthropic/ESA не используются. Текущее состояние источников — docs/phase2/source-health.json и release-sources.json.

Сохраняются заголовок, ссылка, дата публикации и короткий доступный фрагмент. Учитывается московский календарный день, включая релизы поздним вечером UTC предыдущей даты. Дата обновления RSS не подменяет дату публикации. Перед выдачей проверяются HTTPS, разрешённый публичный домен, redirects, robots.txt, доступность статьи и публикационная метаинформация; paywall/403 не обходятся. URL должен присутствовать в собранных публикациях или реальных аннотациях web_search. Модель не может добавить произвольную непроверенную ссылку. Повторы объединяются; старые события не добавляются ради числа. Дата события отдельно не подтверждена, если источник не позволяет её установить; дата публикации показывается у ссылки. Для релизов публикация релиза сама является датируемым событием. Для политических новостей с одним независимым издателем прямо сообщается о недостатке независимых подтверждений.

Цель — 10–15 политических и 5–10 ИИ/других событий. Реальное число может быть меньше: строгая проверка текущей даты/ссылок и доступность первоисточников важнее наполнения. На контрольном прогоне подтверждено по три события в каждой категории. Интерпретация и выбор важности остаются работой GPT; программная проверка ссылки/публикационной даты не является абсолютной гарантией всех фактов статьи.

Кэш хранится локально под DPAPI 15 минут и привязан к категории, нормализованному запросу и московской дате. Кэшированный ответ не вызывает модель. Локальное ограничение по умолчанию — 12 попыток GPT в сутки, изменяется в настройках; реальные квоты Plus/Pro могут быть строже. Модельные ошибки и неудачные попытки учитываются консервативно. OAuth и bearer не журналируются, временные диагностические данные защищены DPAPI.

## Windows — работа без терминала

Приложение: `D:\TelegramNewsBotCodex\dist\WhatsInterestingWorker\WhatsInterestingWorker.exe`. Обычный запуск — ярлык «Что интересного» на рабочем столе, он передаёт --start. При сохранённом входе обработчик запускается сам; иначе нажмите «Войти через ChatGPT», завершите вход в системном браузере и лично разрешите использование подписки. Возвращайтесь в приложение, нажмите «Проверить подключение», выберите доступную модель в «Настройках» и нажмите «Запустить».

«Остановить» прекращает получение заданий и текущую модельную обработку. Закрытие окна сворачивает его в трей; «Выход» в меню трея останавливает worker и завершает приложение. «Отключить ChatGPT» удаляет локальные токены, сохраняя регистрацию и host ID для повторного входа. Для полного отзыва разрешения используйте кнопку настроек использования ChatGPT. Автозапуск и запуск в трее включаются пользователем в настройках; без его выбора Windows Run не менялся. Старое приложение Telegram-бота и его EXE сохранены; рекомендуется пользоваться новым Mini App, чтобы не запускать параллельные запросы старой версии через одну OAuth-регистрацию.

## Фактические проверки

- 20 TypeScript/Vitest тестов и 17 Python-тестов. Проверяются подпись/ID/срок Telegram, сетевые ошибки, обязательный SSE completed, streamed quota errors, запрет модели после остановки, ограничение источников/дат, кэш без модели, локальный дневной лимит и однократный RSS fallback. TypeScript/Vite build проходит.
- Реальный OAuth inference без API-ключа, реальный web_search, реальный каталог аккаунта.
- Реальные задания Supabase → Windows → GPT → Supabase: все три категории completed, mode=news, gpt-6-luna. Ссылки и публикационные даты прошли проверки. Повтор политики вернул cacheHit=true. Первые ИИ/other прогоны были отклонены, пока не исправлены полнота лент и проверка первоисточников; тестовые ответы вместо ошибок не возвращались.
- Реальные PostgreSQL проверки в rollback-транзакции: запрет параллельного claim, неверного/старого lease, повторное завершение и offline. Тестовые строки транзакции не сохранены.
- Реальные HTTPS отказы: неверный worker bearer — 401, вызов worker из browser Origin — 403, offline news — 503/WORKER_OFFLINE. Погода после изменения backend по-прежнему mode=live.
- EXE собран PyInstaller, smoke и start/stop self-test завершились с кодом 0. PE subsystem=2 (Windows GUI), консоль не требуется. Нативный UI Automation прочитал запущенное окно и состояние worker, но автоматический клик Windows-инструмента оказался недоступен из-за отсутствующей геометрии окна; это не выдаётся за успешный ручной клик. Lifecycle проверен реальными слотами приложения через self-test.
- Security advisors: нет WARN/ERROR; INFO о включённом RLS без разрешающих политик ожидаемы. Токены проверяются отдельным сканированием перед публикацией. Изменения опубликованы по прежнему HTTPS URL через Actions; окончательная проверка в Telegram отражается в финальном отчёте.

Не проверены заранее переход аккаунта на Plus в будущую дату, все возможные квоты OpenAI, длительный обрыв сети/нагрузка на сутки и все сочетания WebView/тем. Автозапуск поддерживается, но не включался без выбора пользователя. Не обещается заданное число сегодняшних событий при недостатке подтверждений.

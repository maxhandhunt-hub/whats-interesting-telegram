# Будущий обработчик на Windows

В версии 0.1 локального ИИ-обработчика нет. Задание создаётся в статусе processing, выполняется Edge Function и завершается completed/failed. queued предусмотрен схемой для следующей версии. Никакие запросы к Codex или Claude автоматически не выполняются.

Следующий этап потребует отдельной авторизации локального worker, которая не должна использовать Telegram initData или серверный ключ Supabase на публичном клиенте. Предлагаемый интерфейс: исходящий POST /worker/claim с короткоживущим ограниченным worker-токеном; сервер атомарно выдаёт одно queued-задание, устанавливает processing и lease_until; worker периодически продлевает lease и делает исходящий POST /worker/complete с ID задания, lease-токеном и проверенным JSON-ответом. Повторный complete должен быть идемпотентным. Потерянные lease возвращаются в очередь с ограниченным числом попыток.

Эти endpoints в текущей версии отсутствуют намеренно: публичного административного входа нет. Перед добавлением необходимо мигрировать lease-поля, определить scope/ротацию токена, гарантировать проверку источников и отдельно согласовать механизм ИИ. Порты Windows/роутера не открываются, домашний IP не публикуется. Браузер продолжит получать статус и ответ через существующий защищённый интерфейс.
